# 版本墙（S-05）

首页第 2 屏的 40 张小图，以及第 3 屏背后那面灰墙，用的是同一份数据。

| 文件 | 内容 |
|---|---|
| `tiles.json` | **定稿数据。** 每张小图的位置、尺寸、比例、底色、字色、模板名、语言、内部 HTML；另有版面参数和三个计数 |
| `generate_wall.py` | 设计侧生成 `tiles.json` 的脚本，只用 Python 标准库。在本目录里跑 `python3 generate_wall.py` 会重新生成 `tiles.json` 和 `preview.html` |
| `preview.html` | 把 40 张拼在 1440×900 里的预览，不含页头和计数块 |

## 这面墙是怎么排的

它是手排的，不是随机切出来的。脚本里没有随机数，同样的脚本永远得到同样的结果。

- **四种真实的广告比例**：1:1、4:5、9:16、1.91:1。每张小图的高按比例从宽算出来，取整。
- **8 条竖带**（`layout.strips`）：左边三条、中间两条、右边三条，离母版越远越窄。每条带里一行一行往上或往下排，行与行之间留 4px；一行可以是一张，也可以是两张等高的并排。
- **三处跨带**，所以竖缝不会贯穿整屏：中间的母版（跨中间两条带，500×500）、左下的横幅、右边的两张横幅。
- **墙比屏幕大**：最左、最右两条带，以及每条带的头和尾，都伸到 1440×900 外面，由屏幕裁掉。`tiles.json` 里的 `left`、`top` 会出现负数，宽高加起来也会超过屏幕，这是对的。
- **左下角 428×146 留给计数块**（`layout.counterBlock`），左边三条带从它的上沿往上排。

## 两张特殊的小图

| 字段 | 是哪一张 | 用在哪 |
|---|---|---|
| `keyVisual: true` | 中间最大的母版（小号塞软木塞） | 第 2 屏的动画从它开始：先只有它，其余的从它背后飞出来 |
| `winner: true` | 右下那张钴蓝横幅「Mute the city.」 | 第 3 屏里被抽出来放大的就是它；它在灰墙里的位置空着 |

## 移植要求

1. 构建时生成静态 HTML，线上不跑任何生成逻辑。
2. **以 `tiles.json` 为准做快照测试。** 最简单的做法是构建脚本直接读 `tiles.json` 输出。脚本里没有随机数，把版面逻辑移植成 TypeScript 也能逐张对上，但没有必要。
3. 三个计数从结果里数，不手写：版本数是 `tiles` 的张数，语言数是 `language` 去重后的个数（没有标题的小图是 null，不算），尺寸数是 `ratio` 去重后的个数。现在是 40、7、4。
4. 图片路径在 `tiles.json` 里写的是 `../assets/img/…`，移植时换成站点自己的图片路径。
5. 外层容器是 1440×900、`overflow: hidden`、深色底（#1C1C1B）。小图的 4px 缝靠位置留出来，不是边框。
6. 墙里只有广告图片和产品图，没有达人视频素材。加新图时保持这一条（`assets/manifest.json` 里 `kind` 是 `creator-…` 的不能进墙）。
7. 中日韩标题只在词与词之间换行：数据里已经用 `inline-block` 包好，保留即可。阿拉伯语标题带 `dir="rtl"` 并且右对齐，也保留。
8. 压在页头胶囊下面的小图不放标题，或者把标题放在胶囊下方；右下角被菜单按钮盖住的那一张把产品放在上半部。这些已经体现在数据里，改版面时注意别破坏。
9. 左边缘那张只露出半截标题的小图是故意的，见 `copy.md`。
