# 版本墙（S-05）

首页第 2 屏的 40 张小图，以及第 3 屏背后那面灰墙，用的是同一份数据。

| 文件 | 内容 |
|---|---|
| `tiles.json` | **定稿数据。** 每张小图的位置、尺寸、底色、字色、模板名、内部 HTML，以及格子参数和三个计数 |
| `generate_wall.py` | 设计侧生成 `tiles.json` 的脚本，只用 Python 标准库。在本目录里跑 `python3 generate_wall.py` 会重新生成 `tiles.json` 和 `preview.html` |
| `preview.html` | 把 40 张拼在 1440×900 里的预览，不含页头和计数块 |

## 怎么生成的

- 画面是 10 列 × 6 行的格子，每格 144×150，格间 4px 的缝露出深色底。左下角 3 格留给计数块。
- `pack()` 用固定种子（170）把格子切成四种尺寸：1×1、1×2、2×1、2×2。
- 每种尺寸有一组模板轮流套：产品图加标题、纯文字、产品特写、广告场景图等。底色在六个颜色里轮换，标题在七种语言里轮换。
- 压在页头胶囊下面的小图，文字放到底部（脚本里的 `top` 标记）。右下角被菜单按钮盖住的那一格不放文字。

## 移植要求

1. 构建时生成静态 HTML，线上不跑任何生成逻辑。
2. **以 `tiles.json` 为准做快照测试。** 最简单的做法是构建脚本直接读 `tiles.json` 输出；如果把 `pack()` 和模板也移植成 TypeScript，Python 的随机数序列很难原样复现，那就把 `tiles.json` 里的格子划分当作输入，只移植模板。
3. 三个计数（版本数、语言数、尺寸数）从结果里数：现在是 40、7、4。
4. 图片路径在 `tiles.json` 里写的是 `../assets/img/…`，移植时换成站点自己的图片路径。
5. 墙里只有广告图片和产品图，没有达人视频素材。加新图时保持这一条（`assets/manifest.json` 里 `kind` 是 `creator-…` 的不能进墙）。
6. 中日韩标题只在词与词之间换行：数据里已经用 `inline-block` 包好，保留即可。
