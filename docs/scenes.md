# 滚动场景的骨架

首页每屏的滚动动效（第 3 批，M-02 起）都搭在这套骨架上。规则来自 `design/motion.md`「通用规则」；这里写的是代码怎么对应、新的一屏怎么接入。代码在 `src/scenes/`。

M-01 只搭了骨架，带一个示例场景（`/parts/scene/`）。首页各屏还没有接入，首页现在还是静态版。

## 三条规则

1. **每屏一个场景模块。** 外层的高度是若干个屏高，里面一层用 CSS `position: sticky` 固定在屏幕上。滚过外层的这一段，进度 `p` 从 0 走到 1：外层的顶边到屏幕顶边时是 0，外层的底边到屏幕底边时是 1。
2. **GSAP + ScrollTrigger 只负责把这一屏的时间线绑到 `p`**（`scrub`）。不用 ScrollTrigger 的 `pin`，测试会查代码里有没有出现。
3. **退路是静态帧。** 下面任何一种情况，页面都不请求 GSAP 的文件，每屏照静态版的样子排，占一屏的位置：

| 情况                     | 怎么判断                                                                          |
| :----------------------- | :-------------------------------------------------------------------------------- |
| 系统开了「减少动态效果」 | 媒体查询 `(prefers-reduced-motion: reduce)`                                       |
| 手机                     | 窗口宽度在 768 以下；或者主要靠手指操作、没有悬停的设备（横过来的手机和平板也算） |
| 微信内置浏览器           | 浏览器标识里有 `MicroMessenger`（手机和电脑上的微信都算）                         |
| 浏览器没开脚本           | 动效要脚本来开，没有脚本就是静态帧                                                |
| GSAP 没加载成功          | 运行时把整页改回静态帧                                                            |
| 某一屏的场景写错了       | 同上，整页退回静态帧，错误打在控制台里（比如时间线超过了 1、页面上的元素找不到）  |

「手机」这一条交接包没有给断点，上面两条是实现时定的，见文末「还没定的」。

开着页面时环境变了（窗口拉窄、开关「减少动态效果」），页面会跟着在动效和静态帧之间切换。

## 给一屏加动效

以首屏为例。只动这一屏自己的两个文件，几屏同时做不会互相撞。

**1. 把这一屏包进 `Scene`。** 在这一屏的组件里（`src/home/HeroScreen.astro`）：

```astro
<Scene name="01-hero" length={6}>
  <Screen name="01-hero" background="hero-light">
    <!-- 原来的内容不动：它就是静态帧 -->
  </Screen>
</Scene>
```

`length` 是外层有几个屏高，滚完「`length` − 1」个屏高走完这一屏。`name` 对应下一步的文件名；没有这个文件，构建时就报错。

**2. 写场景模块。** 新建 `src/home/01-hero.scene.ts`（放在 `src/` 下哪里都行，文件名是 `<场景名>.scene.ts`）：

```ts
import { defineScene } from '../scenes/define';

export default defineScene(({ sticky, timeline, onProgress }) => {
  const boards = sticky.querySelectorAll('[data-board]');

  // 时间线总长是 1：位置和时长直接写进度，照 motion.md 的表格抄。
  // 「p < 0.1：一摞板上下炸开」
  timeline.fromTo(
    boards,
    { y: 0 },
    { y: (index) => index * 40, duration: 0.1 },
    0,
  );

  // 时间线不好表达的事（按公式摆位置、换数字、换文字）放 onProgress
  const counter = sticky.querySelector('[data-counter]')!;
  const still = counter.textContent;
  onProgress((p) => {
    counter.textContent = `0${Math.min(6, 1 + Math.floor(p * 6))} / 06`;
  });

  // 自己动手改的东西，退回静态帧时要改回去
  return () => {
    counter.textContent = still;
  };
});
```

- `sticky` 是这一屏固定在屏幕上的那一层，要动的元素都从它往下找。
- `timeline` 已经绑好滚动进度。默认匀速（`ease: 'none'`），要缓动的在那一段上自己写。时间线超过 1 会报错并退回静态帧。
- GSAP 改过的样式，退回静态帧时自动还原。不经 GSAP 改的（文字、类名）要像上面那样返回一个函数改回去。
- 场景模块只在动效模式下才加载，里面可以再引 GSAP 的其他插件；别的文件只能引 GSAP 的类型。

**3. 处理「GSAP 还没下载完」的那一小会儿。** 动效模式下，页面一打开外层就已经撑高、里面那层已经固定，但 GSAP 是之后才下载的。这一小会儿画面还是静态帧。进度 0 的样子和静态帧不一样的屏（比如第 2 屏静态帧是铺满的墙，进度 0 只有母版一张），要避免先闪一下静态帧：

- 能用样式表达的，写进度 0 的初始样式，选择器前面加 `:root[data-scene-mode='motion']`。
- 文字这类样式表达不了的，在时间线建好之前先藏起来：外层在时间线建好后才有 `data-scene-ready` 属性，用 `[data-scene]:not([data-scene-ready])` 选中「还没建好」的时候。

示例页两种都用了，见 `src/pages/parts/scene.astro` 末尾的样式。

**4. 检查。** 桌面上滚一遍；再用手机宽度、开「减少动态效果」各看一次，应该和接入前的静态版一样，开发者工具的网络面板里没有 GSAP 的文件。

## 画布怎么放进固定层

静态帧下，首页的画布按页面宽度缩放（`--home-scale`，「页面宽度 ÷ 1440」），和接入前一样。

动效模式下，固定层是一个屏高，画布照两份小样的做法按「放得下」的比例居中：`--scene-scale` 是「宽 ÷ 1440」和「高 ÷ 900」里小的那个。屏幕不是 16:10 时，画布两边或上下会留出这一屏的底色。例如 1920×1080 的窗口，画布是 1728×1080，两边各留 96。

## GSAP

- 版本：`gsap` 3.15.1，经 npm 打包进站点，不引在线地址。ScrollTrigger 在同一个包里。
- 许可：GSAP 自家的免费许可（Standard "no charge" license，不是 MIT），全文见 gsap.com 的 standard-license 页。官网这种用途允许；不能转卖，也不能拿它做动效工具类的竞品。
- 体积：单独一个文件，压缩前约 113 KB，gzip 后约 44 KB，只在动效模式下才下载。静态帧下页面只加载约 4 KB 的运行时入口。

## 还没定的

这几条骨架按最稳妥的做法先实现了，等设计侧确认；改主意时只用改 `src/scenes/mode.ts` 或 `Screen.astro` 里的一处。

1. **「手机」的界线。** 现在是 768 以下的窗口，加上所有主要靠手指操作的设备。平板因此也是静态帧。
2. **屏幕不是 16:10 时画布旁边的留边。** 纸色底的屏看不出来；第 2、3 屏的图片墙原本是「铺到屏幕外面、四边被裁」，留边处会露出底色，接入那两屏时要看效果。
3. **运行时的入口脚本本身没加载成功**（网络中断）时，页面停在「外层撑高、里面固定着静态帧」的状态：能正常往下滚，只是这一屏要多滚几个屏高。GSAP 没加载成功的情况已经处理了，这一种没有。
