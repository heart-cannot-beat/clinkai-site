# 截图对比

站点的每一屏和 `design/screens/` 里对应的设计稿逐像素比，差得超过阈值就失败。代码在 `tests/visual/`，用 Playwright（Chromium）。CI 里是单独的一个 job。

现在比 12 张：

- 首页 6 屏，第 3 屏的两拍各算一屏，共 7 张：`01-hero`、`02-wall`、`03-winner`、`03b-next-round`、`04-creators`、`05-layers`、`06-ending`。
- 「我们的产品」一页三屏：`page-products`、`page-products-ads`、`page-products-creators`。
- 「关于我们」：`page-about`。
- 「预约沟通」：`page-contact`。

## 怎么跑

```sh
npx playwright install chromium   # 第一次，或者 Playwright 升级之后
npm run test:visual               # 先构建，再比
```

跑完终端里有一张表，列出每一屏的差异数字。每一屏的基准图、站点截图、差异图在 `test-results/screens-<屏名>/`；`npx playwright show-report` 打开报告，能把基准图和站点截图左右对照着看。这两个文件夹不进仓库。

只跑一屏：`npx playwright test -g 04-creators`（不会重新构建，改了站点代码要先 `npm run build`）。

## 基准图是什么

**基准图不存在仓库里，每次跑的时候现渲染：** 同一次运行里，同一个浏览器先给站点的一屏截图，再打开 `design/screens/<屏名>.html` 渲染出基准图，两张比。

这样做的原因：

- **设计稿就是标准，不需要另存一份图。** 交接包更新了，基准自动跟着变；站点没跟上，对比就失败。
- **同一台机器、同一个浏览器画出来的两张图才能逐像素比。** 文字的抗锯齿、系统字体，macOS 和 CI 的 Linux 都不一样。存一份在某台机器上渲染的图，换一台机器就全是差异。
- `design/refs/*.jpg` 不能用：那是近似图，渲染时没有 Inter Tight（`design/README.md`「参考截图的局限」）。

渲染基准图时不改 `design/` 里的任何文件，只在浏览器里做三件事：

1. **字体换成站点自托管的那一份。** 设计稿从谷歌字体的在线地址加载 Inter Tight 和 Noto Sans SC。这个请求被接住，换成站点用的 `@fontsource/inter-tight`（同一个 npm 包、同一份 `400.css`）。不连外网。
2. **视频不给，停在封面上。** 见下面「04 屏的视频」。
3. **把那一帧挪到和站点那一屏相同的页面位置。** 见下面「为什么要挪位置、重画、关掉 LCD 文字」。

## 中文字体怎么处理

站点只自托管 Inter Tight，中文（还有版本墙里的日文、韩文、阿拉伯文，以及 Inter Tight 拉丁子集里没有的箭头 `↗` `→`）落到系统字体（`CLAUDE.md`「技术约定」）。设计稿原本用在线的 Noto Sans SC 画这些字。

对比时**两边都不加载 Noto Sans SC**，都落到跑测试这台机器的系统字体：macOS 上是苹方，CI 上是那台机器装的字体（job 里装了 Noto Sans CJK）。两边用的是同一个字体，所以中文字形不产生差异，不需要为它放宽阈值，也不需要划掉文字区域。

代价是：这个对比查不出「系统字体和设计稿的 Noto Sans SC 长得不一样」。那是「中文用系统字体兜底」这条约定带来的，不是实现的偏差（P-01 在 Issue #12 第 5 条里报过：macOS 上胶囊页头因此窄约 13px）。

CI 的机器默认没有中日韩字体。`visual` job 会装 `fonts-noto-cjk`，并在跑之前确认中文、日文、韩文、阿拉伯文都有字体可用；没有就直接失败，免得两边都画成方框、比了等于没比。

## 截图前做的事

设计稿和站点走同一套步骤（`capture.ts`）：

- 等字体加载完，确认 Inter Tight 真的加载了、没有加载失败的字体。
- 这一屏里的图片全部改成立即加载，等它们加载、解码完；有图片没加载出来就失败。站点的图片大多是延迟加载的，有些排在画布外面，不改的话永远不会加载。
- 确认视频停在封面上。
- 整页重画一遍，再截图。

另外，站点请求了站外地址、或者请求的文件不存在，这条测试也失败。

### 04 屏的视频

04 屏中间是一条自动播放的视频，两边播到哪一帧不可能一样。对比时两边都停在封面上：

- 视频文件一律不给（`routes.ts`）。设计稿的 `<video>` 加载不到视频，显示的就是 `poster` 和垫在下面的那张封面图。
- 浏览器开着「减少动态效果」。站点的规则是这时不播、只显示封面图（`design/motion.md` 04 屏的退路 1）。

截图前会检查两边的视频确实没在播、也没播过。

开着「减少动态效果」还有一个原因：滚动动效做完以后，站点只有在这个设置下才显示静态帧，而设计稿的每个文件正是静态的那一帧。

### 为什么要挪位置、重画、关掉 LCD 文字

这三件事是实测出来的。不做的话，站点和设计稿明明画的是同一个东西，也会差出几个到上万个像素：

- **位置。** 浏览器画大字的斜边、画渐变时的抖动，结果和这块东西在整页里的纵向位置有关。设计稿的那一帧贴着页面顶部，站点的 06 屏在往下 5400px 的地方：不挪的话 06 屏差 2074 个像素（最大差值 58），04 屏差 4395 个。把设计稿那一帧挪到同样的位置（给 `<body>` 加内边距），这些差异全部消失。
- **重画。** 图片解码完、图片被藏起来，浏览器只重画变了的那几块；局部重画时形状边缘的抗锯齿和之前画过什么有关。不重画的话 01 屏时有时无地差 18 到 85 个像素（差值 1–2），02 屏的胶囊页头边上偶尔差 4 个像素（差值到 24）。截图前把 `<body>` 藏起来再显示，逼浏览器整页重画，结果就稳定了。
- **LCD 文字。** Linux 上 Chromium 按图层决定小字用不用 LCD 次像素抗锯齿（字边带彩色）。站点整页和设计稿单屏的图层不一样：CI 上 03b 之后的四屏，设计稿那页的小字用了 LCD，站点那页是灰度，每屏差一万多个像素（最大差值到 155）。测试用的浏览器加了 `--disable-lcd-text`，两边都用灰度。macOS 本来就不用 LCD，不受影响。

## 比两遍，各有各的阈值

一个像素的「差值」是红、绿、蓝三个通道里差得最多的那个，0 到 255。阈值在 `tests/visual/screens.ts`。

**第一遍：藏起图片，只比版式、文字和色块。** 两边都把 `<img>` 和 `<video>` 设成不可见（位置还占着）再截图。

- 阈值：差值超过 2 的像素不能多于 16 个。除了 `page-contact`（见下面「站点和设计稿有意不一样的地方」），所有屏一样。
- 实测：十一屏都一个像素不差；`page-contact` 差 26 个。
- 余量只为挡住浏览器抗锯齿偶尔的抖动。16 个像素比页面上最小的东西还小（8px 的圆点约 50 个像素），所以挪了位置、改了颜色、换了字号，都过不了这一遍。

**第二遍：带图片比整屏。** 查图片对不对、位置和裁切对不对。

- 站点的图片经过图片管线转成了 AVIF、按显示大小缩过（`docs/media.md`），设计稿直接用原图。两边在图里明暗交界的地方有压缩噪点，所以容差放宽到 24，上限按屏定，大约是实测值的 1.7 倍。
- 02 屏每次跑会有十几个像素的出入（设计稿那边原图缩小时的取样不完全固定）。

## 站点和设计稿有意不一样的地方

设计稿里有几处【待填】的占位框（虚线框里写着「【待填：年份】」这样的字）。真实信息补齐之前，站点上这些地方整块不显示，不留占位字样（`src/data/about.ts`、`src/data/contact.ts`）。所以这几处不能照着设计稿原样比。处理办法写在 `screens.ts` 里那一屏的配置上，每一项都带着原因：

| 屏             | 设计稿里的东西                               | 怎么处理           |
| :------------- | :------------------------------------------- | :----------------- |
| `page-about`   | 底部四项事实（成立、团队、办公地、投放平台） | 渲染基准图时藏起来 |
| `page-contact` | 左下角的邮箱、微信                           | 渲染基准图时藏起来 |
| `page-contact` | 「月预算」和「怎么联系你」并排的那一行       | 这一行不比         |

两种办法：

- **藏起来（`hiddenInDesign`）。** 渲染基准图时把占位框设成不可见，位置还占着。站点那里本来就什么都不画，所以这一块照样逐像素比：比的是「站点那里确实是空的」。能用这个办法就用这个。
- **不比（`skippedAreas`）。** 设计稿里那一块占的长方形，两遍都跳过；留下来的截图里这一块是一片灰。只用在藏起来也对不上的地方：预算分档没补齐时站点不显示「月预算」，「怎么联系你」占满了整行，和设计稿的两栏排法不一样。这一块里站点画成什么样都不会失败。

信息补齐以后，站点开始显示这些东西，对比会失败（藏起来的那种）：那时把对应的配置删掉，设计稿里也该换成真实内容了。配置里的选择器在设计稿中找不到时，测试也会失败，免得配置悄悄过时。

另有一处不是【待填】，是站点和设计稿差了一点：**`page-contact` 标题后面的句号**，设计稿是 110px 见方，站点上是 109.984px（大小是用 em 算的，被浏览器截到 1/64px），位置也因此偏了 1/64px。圆的边上差 26 个像素，最大差值 11，肉眼看不出来。这一屏第一遍的上限因此放到 40 个（`maxLayoutPixels`），等预约沟通页修好再收回去。

## 失败了怎么看

1. 终端里（CI 里是这次运行的摘要页）的表：哪一屏、哪一遍、差多少。
2. 差异图：超过容差的像素标成红色，底下是变淡的基准图。本地在 `test-results/screens-<屏名>/`，`layout-*` 是第一遍，`with-images-*` 是第二遍；`expected` 是基准图（设计稿），`actual` 是站点。CI 失败时这些文件和报告一起作为构件 `visual-compare` 上传，在运行页面底部下载。
3. 判断是谁该改：
   - 站点改坏了：改站点。
   - 设计稿更新了、站点还没跟上：在对应的 Issue 里同步站点。
   - 改了图片管线的压缩参数，第二遍的噪点变多：重新量一遍，改 `screens.ts` 里那一屏的上限，在 PR 里写明新旧数字。不要为了让 CI 变绿去放宽第一遍的阈值。

## 加一屏

在 `tests/visual/screens.ts` 的 `SCREENS` 里加一项：设计稿的文件名、站点上的地址、这一屏的选择器、第二遍的上限。先填 0 跑一遍，看实测数字，再定上限。用 `src/home/Screen.astro` 画的屏，选择器就是 `[data-screen="<设计稿文件名>"]`。

设计稿的文件里必须只有一帧（`<body>` 下一个块），站点上那一屏的大小要和它一样；大小不一样会直接报错。

## 没有覆盖的

- **只有 Chromium、1440 宽、1 倍屏。** Safari、Firefox、微信内置浏览器、2 倍屏、别的窗口宽度都没有比。
- **只比静态的那一帧。** 滚动过程中的画面、视频播放时的画面不在这里查。
- **字体和设计稿原样不同的地方查不出来。** 见上面「中文字体怎么处理」。
- **手机版没有。** 等手机稿（P-02）。
